# 架构设计

## 总体分层

panguforge 采用五层结构，层间通过明确接口解耦：

| 层 | 目录 | 职责 |
|---|---|---|
| 数学内核 | `core/` | 纯 Python 张量、注意力、MoE、Transformer |
| 算法 | `train/` | 预训练 / SFT / RL 的训练循环与优化器 |
| 数据 | `data/` | tokenizer、数据集、采样与批处理 |
| 算力 | `backends/` | 统一引擎接口，多后端实现 |
| 对外 | `serving/`、`cli/` | HTTP 服务与命令行 |

## 引擎接口

所有后端实现统一的 `BaseEngine` 接口：

```python
class BaseEngine:
    def compute_loss(self, batch): ...   # 训练损失
    def train_step(self, batch): ...     # 单步训练，返回指标
    def metrics(self): ...               # 当前指标
    def next_token(self, prefix): ...    # 预测下一 token
    def generate(self, prompt, max_tokens): ...
    def reward(self, prompt, completion): ...   # RL 奖励
    def reinforce(self, prompt, completion, delta): ...
```

`train/` 只依赖这个接口，因此切换 `mock` → `cpu` → `ascend` 无需改动训练代码。

## MoE 前向

```
输入 ids
  └─ Embedding
      └─ × N 层 TransformerBlock
           ├─ 多头自注意力（可替换为 SWA / DSA）
           ├─ 残差连接
           ├─ MoE FFN：Top-K 路由 → 激活 K 个 SwiGLU 专家 → 加权求和
           └─ 残差连接
      └─ 最终 RMSNorm
          └─ LM Head → logits
```

## 确定性训练信号

mock 后端将「skill」定义为正确下一 token 的概率：

- `loss = -log(skill)`，skill 上升 ⇒ loss 下降
- `train_step` 使 `skill += lr * (1 - skill)`，单调趋 1
- 因此任意一次运行都可量化「模型学到了」

## 分布式

- `distributed/dist.py`：进程组抽象，单进程自动降级
- `data_parallel.py`：批次分片 + 指标归约
- `expert_parallel.py`：MoE 专家按 rank 分片
- `collective.py`：集合通信桩（单进程 no-op）

## 扩展指南

1. 新增后端：继承 `BaseEngine` 并用 `@register_backend("名字")` 注册。
2. 新增注意力：继承 `MultiHeadAttention`，覆盖 `__call__` 传入自定义 mask。
3. 新增 RL 算法：在 `train/` 中实现 `xxx_update(engine, prompts, ...)` 并在 `RLLoop` 路由。
